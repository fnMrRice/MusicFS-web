# Web 手动验收

先按 [Server 本地运行说明](../../server/docs/operations/running.md) 启动并扫描。目录、扫描和插件仍由 Server 管理。以下是人工操作清单，自动化证据见 [React 交付记录](react-validation.md)，不代表已完成人工听音。

| 操作 | 预期 |
| --- | --- |
| 登录和刷新页面 | 检查 MusicFS API v1，就绪后交换凭据；输入清空，刷新用 HttpOnly Cookie 恢复 |
| 滚动曲目列表 | 品牌、账号、顶部工具和播放栏保持可见；临近末尾自动追加，无页码／加载更多按钮 |
| 勾选和全选 | 不触发播放；全选只作用于已经返回的曲目，追加后部分选中；刷新和来源改变清空选择 |
| 侧栏分组、账号菜单 | 两组独立折叠，新建歌单不触发折叠；账号右键或三点打开菜单，Escape／外部点击关闭 |
| 设置和换肤 | 顶部仅两个图标；主题和本机偏好按用户隔离；窄屏和键盘仍可到达控件 |
| 播放 WAV、暂停、继续、音量 | 自定义控件工作，音频随暂停停止推进；切换页面或刷新列表不打断播放 |
| 播放处理输出并定位 | 在设置请求 -6 dB，下一次选曲生效；底部进度始终代表曲目时间，定位替换输出并保留暂停意图 |
| 播放 NCM MP3／FLAC | 分别显示服务端解密输出／服务端解密并转码输出；纯解密不被当作增益处理 |
| 播放损坏文件 | 明确失败，提供从头播放和停止；切换正常曲目可恢复 |
| 队列 | 勾选加入队列，打开队列选曲；上一首／下一首／列表循环使用稳定来源身份。切页保留，刷新从固定键 `musicfs:playback-queue:v1` 恢复顺序、重复项、选中索引、模式、随机历史和下一首优先项；不自动播放或恢复旧流地址 |
| 搜索 | 输入法组合期间 Enter 不提交；四类型页签保留关键词；既有在线曲目按来源分区，未支持类型说明原因 |
| 推荐 | 按来源卡片展示，过期／部分失败独立可辨；打开只预览，导入需要显式点击 |
| 歌单 | 选择曲目新建歌单、改名、调整聚合规则、更新快照；旧修订冲突显示错误，不伪装成功 |
| 远程同步 | 导入后显式同步；创建任务不算完成，终态和上次成功时间可辨，失败保留旧内容 |
| 退出／401 | 停止音频，清空队列及其本地缓存、身份、当前用户数据缓存；下一账号不读取上一账号队列、偏好和搜索记录 |
| 更换 API 地址 | 清空队列及其本地缓存；固定键仅保存一份，不按账号或服务地址另存多份，切回旧地址不恢复旧队列 |

建议在 1440×900、1280×800 和窄视口下检查中文长标题、无封面占位、错误提示及 Tab 焦点。歌词面板当前按文本显示已选内容，不承诺逐句时间同步。已知接口缺口见 [Server 交接](../../server/docs/contracts/web-integration.md)。
