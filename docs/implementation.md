# MusicFS Web 分阶段实现计划

状态：实现前计划，2026-10-09；本文没有把接口、文件、测试或启动命令描述为已经存在。阶段编号与 [跨端架构](../../docs/architecture.md)、[Server 实现计划](../../server/docs/implementation.md) 对齐。本文只安排 Web 及其与 Server 的联调，不安排桌面 Client 实现。

## 1. 本期交付范围

本期提供一个简单页面：连接并登录 Server、显示来源文件列表、刷新/翻页、选择一首歌，通过浏览器播放、暂停、定位和停止。页面使用普通 HTML 布局、少量 CSS 与原生音频控件，先验证完整播放能力。

第一条可运行链路是“Server 配置音乐目录 → Local Files Provider 扫描 → Web 列表 → 点击播放 → 原始兼容音频播放”。第二条链路是“浏览器不支持输入格式或明确请求 DSP → Server 插件链处理 → Web 播放新输出 → 按曲目时间重新定位”。P3 与 P4 分别设实际浏览器验收门槛，不能以静态假列表、模拟媒体事件或只有下载成功作为完成依据。

本期不做主题、桌面宿主适配、复杂歌单编辑、播放队列、动画、歌词同步、封面墙、推荐首页、可视化插件安装和平台账号管理。P5—P7 的后端功能仍需有可测的接口；Web 只补齐影响文件列表和播放的必要状态。音乐目录、扫描和插件参数先由 Server 配置文件或管理命令设置。

### 1.1 技术起点与待验证项

- 建议使用 TypeScript、Vite 与原生 DOM，采用 `vanilla-ts` 起点；不引入前端框架或组件库作为首轮播放的前置条件。版本在 P1 选定并锁定，记录对应 Node.js 版本及包管理器。[Vite 官方入门](https://vite.dev/guide/)
- 使用一个活动 `HTMLAudioElement`，先用原生 `controls`；应用控制会话、来源版本、播放代次和错误，浏览器负责媒体解码与输出。`play()` 的结果和媒体事件都必须处理，调用成功不代表已经开始发声。[HTML 媒体元素规范](https://html.spec.whatwg.org/multipage/media.html#media-elements)
- 不预设 MP3、AAC、Opus 或某个容器在所有浏览器可用。P0 选择样本，P3/P4 记录操作系统、浏览器版本、输出 MIME/容器/编码及实际结果。
- 首版同源部署；开发由 Vite 将 `/api` 请求代理至 Go Server。生产构建产物由静态站点配合同源反向代理部署，也可交给 Server 可选的 `--web-root` 托管，方便本地试运行。Server 只接收 Web 构建产物，不接管 Web 源码。[Vite 开发代理](https://vite.dev/config/server-options#server-proxy)
- 不默认加入 MSE、Service Worker、离线缓存、Web Audio DSP 或浏览器 FFmpeg。若 P4 的输出组合不能通过普通媒体元素播放，先调整 Server 输出方案；确需增加浏览器传输适配器时单独记录证据与成本。

## 4. P0：锁定最小跨端契约

### W0.1 明确接口边界

在 Server 发布的 OpenAPI 中逐项核对下表；这里是实现目标，不是已上线接口。业务前缀统一为 `/api/v1`，HTTP 失败解析结构化 `code/message/requestId/retryAfter`，页面显示可操作的中文说明，开发日志采用英文且不输出凭据。

| 接口 | Web 行为与关键响应 |
| --- | --- |
| `GET /health/ready` | 检查实例就绪、身份和协议版本；不能据此推断已登录 |
| `POST /auth/session` | 仅在登录时用显式输入的 owner bootstrap token 发送 `Authorization: Bearer …`，获得会话 cookie 与 `csrfToken` |
| `GET /auth/session` | 页面加载时恢复当前身份、权限和 CSRF 值；未登录进入登录表单 |
| `DELETE /auth/session` | 撤销登录会话，清理页面数据、停止音频 |
| `GET /provider-instances` | 读取当前用户可见的来源实例、能力与状态，用于选择列表来源 |
| `GET /source-tracks?providerInstanceId=…&cursor=…&limit=100` | 获取 `items/nextCursor/libraryRevision`；游标固定同一库修订 |
| `POST /playback/sessions` | 提交 `sourceTrackId`、实际浏览器能力及偏好，获取会话和当前播放描述 |
| `POST /playback/sessions/{id}/seek` | 仅在 timeRestart 需要时提交当前 `attemptId` 和曲目 `positionMs`，接受新描述 |
| `POST /playback/sessions/{id}/recover` | 提交当前尝试、可观察故障及曲目位置，接受 Server 恢复决定 |
| `DELETE /playback/sessions/{id}` | 停止或离开当前曲目时释放会话；服务端还需有超时兜底 |
| `GET streamUrl` | 媒体元素按返回地址读取固定输出；不拼接路径、不追加 owner token |

列表条目至少包含 `sourceTrackId/providerInstanceId/displayName/availability`，以及 `title/artists/durationMs/codec/container/bitrateBps/assetId`；元信息或资产尚未探测完成时允许相应值为 null，`recordingId` 为可选且可空字段。文件名称只作展示，播放使用来源曲目 ID；不接收 Server 绝对磁盘路径作为公开播放地址。未知时长/码率显示“未知”，不能默认为零或阻止播放。

播放描述必须核对 `sessionId`、`attemptId`、`assetId`、`representationId`、`deliveryMode`、`outputProfile`、`streamUrl`、`expiresAt`、`seekMode`、`seekableRange`、`positionOriginMs`、`effectiveProcessing` 和 `resumeDecision`。绝对时间为 UTC ISO 8601；音频位置用毫秒，媒体元素的秒值只在适配边界转换。

### W0.2 确定鉴权与同源方式

1. 登录 token 只在登录请求期间保留于表单/内存；成功后清空输入，不写 URL、localStorage、日志或前端构建环境变量。
2. Server 设置 `HttpOnly`、`SameSite=Strict` 会话 cookie；正式 HTTPS 部署还必须设置 `Secure`，loopback HTTP 开发例外由配置明确限定。
3. 首次 `POST /auth/session` 尚无会话 CSRF，使用显式 Bearer 引导凭据与严格允许列表内的 `Origin` 校验，不要求预先取得 CSRF。登录后的同源 JSON 请求携带 cookie，所有状态修改请求带 `X-CSRF-Token` 并校验 `Origin`，退出同样执行校验。
4. `<audio>` 不支持由应用任意附加 `Authorization` 请求头，因此最小方案使用同源、cookie 鉴权的音频路由；不先下载整首文件为 Blob 来绕过鉴权。
5. 开发代理保留浏览器实际 Origin，Server 精确配置允许的开发 Origin；不要用关闭 CSRF 或任意 Origin 放行解决代理问题。
6. 401 清理鉴权状态并显示重新登录，403 显示权限不足；流失效、编码不支持和登录失效分别处理。浏览器无法给出流的具体 HTTP 原因时向 Server 报告观察结果。

### W0.3 定义固定修订分页

第一请求不带游标，保存响应 `libraryRevision`。后续请求只传当前响应提供的游标，按 `sourceTrackId` 维护稳定展示身份，不自行计算页码。刷新、切换 Provider 或游标失效时取消旧请求，重新读取第一页；不同修订的页不能拼接。旧请求返回时检查列表代次，避免刷新后混入旧页。首期提供“加载更多”，无需无限滚动。

### W0.4 准备可重复媒体样本

计划生成或使用许可明确的短音频：兼容原流、需转码的输入、时长/头部有差异的同源版本、损坏文件和零字节文件。短样本应包含时间定位可识别的分段声音，另准备足够长的样本验证缓冲与取消。样本 README 记录生成方式、授权与摘要；不用私人音乐库、在线付费曲目或平台凭据构建 CI 用例。

**P0 验收：** Server 与 Web 对以上字段、单位、错误、cookie、CSRF、游标和会话回收达成同一契约；至少选定一组 P3 原流与一组 P4 处理后播放样本。使用 Mock 辅助页面开发时，在测试名称和说明中标明，不能计入媒体兼容性结果。

## 5. P1：建立可启动的最小页面

1. **W1.1 工程初始化：** 建立 TypeScript 严格检查、Vite 构建和依赖锁文件，将生成模板入口调整为 `src/app/main.ts` 并更新 `index.html`；测试全部放在根 `tests/`。脚本分开负责开发、类型检查、构建、单元测试与 E2E。使用兼容的固定 Node.js 版本，README 记录实际验证命令；不在文档阶段宣称命令已可用。
2. **W1.2 API 客户端：** 实现 JSON 请求、有限超时、AbortSignal、结构化错误和请求 ID；不要对有副作用的请求自动无限重试。创建/定位/恢复的重试复用同一次逻辑操作的 `Idempotency-Key`。
3. **W1.3 页面骨架：** 一个标题、连接状态、登录表单、列表区域、当前曲目和播放器区域即可。用语义化表格或列表、普通按钮、可见焦点及关联 `label`；不做导航框架和设计系统。
4. **W1.4 鉴权接入：** 先读当前会话；401 时显示登录，提交期间禁止重复操作，失败保留可读原因但不回显密钥。登录成功清空 token，加载列表；刷新页面依靠 cookie 恢复，退出停止媒体并清理身份相关数据。
5. **W1.5 就绪错误：** 区分“正在连接”“Server 未就绪”“版本不兼容”和“未登录”，显示重试入口；失败页面仍可用键盘操作。
6. **W1.6 基础验证：** 单元测试覆盖错误归一、取消和 401；联调验证实际 Set-Cookie、CSRF 失败、刷新恢复和退出，验证输出资源不含 bootstrap token。CI 构建不是登录链路通过的替代证据。

**P1 产物：** 可构建的页面、真实登录链路、API 模块和最小测试配置。此阶段还不能称为可用音乐播放器。

## 6. P2：显示实际扫描结果

1. **W2.1 读取来源：** 通过 `GET /provider-instances` 取得当前用户可见的 Provider；只有一个实例时直接显示，多实例时允许一个简单选择框。本地目录配置和扫描触发先在 Server 完成，Web 不传入任意路径。
2. **W2.2 列表渲染：** 展示名称、可用性和可用的时长/格式/码率，加一个播放按钮。所有名称和错误文本使用文本节点，不能拼进 HTML；未知元信息不隐藏文件。
3. **W2.3 分页与刷新：** 实现 W0.3 固定修订分页、加载更多和取消。刷新时保留上次成功数据并提示正在刷新；请求失败保留旧内容，明确“内容可能不是最新”。
4. **W2.4 空列表与故障：** 区分真正的空库、扫描未完成、来源离线、无权限和接口错误。NAS 离线不显示“已删除全部文件”；损坏曲目按可用性提示，允许其他曲目正常操作。
5. **W2.5 列表与播放器隔离：** 刷新列表不停止当前播放；来源记录更新不直接改活动 `audio.src`。当前会话是否继续或恢复，由 Server 的资产版本与会话契约决定。
6. **W2.6 验证：** 单元测试覆盖乱序页、刷新与下一页竞争、游标失效和空值；E2E 用临时 Server 音乐目录扫描真实样本，再确认名称、翻页和离线状态，不能只用静态 JSON 验收。

**P2 产物：** 可以读取实际扫描库的简单文件列表。扫描进度可以由 Server 管理工具查看；无需增加 Web 扫描管理面板。

## 7. P3：原流与第一个可播放里程碑

### W3.1 能力探测与会话创建

按候选输出的完整 MIME/编码组合调用 `canPlayType()`，上报探测结果以及 `htmlAudio` 传输能力。空结果表示不支持，`maybe/probably` 仅作协商提示；最终要经过真实媒体验证。不要把扩展名、浏览器名称或操作系统名称当作成功证据。

点击文件行的播放按钮后保存用户播放意图，递增播放代次，取消旧控制请求，暂停并卸载旧媒体，释放旧会话，再创建当前曲目的新会话。新请求返回时核对代次；过期返回携带的会话尽力关闭，不能接管播放器。Server 用过期回收兜底，避免网络取消后出现无主会话。

### W3.2 媒体适配器

适配器负责设置 `src`、加载、监听事件和销毁；业务控制器不直接散落操作 DOM。绑定当前代次和尝试的监听器，在替换资源时解绑或重建媒体元素，避免旧媒体事件更新新曲目。`preload` 首期使用适度策略，不主动批量预加载列表中的音频。

加载返回的 `streamUrl` 后按用户意图调用并等待 `play()`，处理自动播放策略拒绝：显示“点击播放”并保持当前会话，不把它计为来源故障。切换产生的主动取消不显示为播放错误。原生控件操作产生的暂停/播放事件也必须更新同一状态。

### W3.3 最小播放状态机

| 状态 | 进入条件 | 页面和后续处理 |
| --- | --- | --- |
| idle | 初始、主动停止完成 | 无活动流，可以选曲 |
| resolving | 创建会话或换源请求 | 显示正在准备，允许停止/切歌 |
| loading | 已设置当前流，等待可播放 | 展示当前曲目，不提前宣称播放成功 |
| playing | 当前代次媒体触发实际播放事件 | 显示进度；等待/暂停/结束都由实际事件驱动 |
| paused | 用户暂停或等待再次手势 | 保留会话与进度，允许继续 |
| buffering | 已开始后发生 waiting/stalled | 显示缓冲；有限超时后报告故障，不立即切源 |
| seeking | 原生定位或等待 timeRestart | 保留最新目标与播放意图；同会话响应仍推进已确认尝试，不展示已被新意图替代的中间位置 |
| recovering | Server 正在处理有限恢复 | 停止重复上报同一次故障，仍可停止/切歌 |
| ended | 当前尝试正常播完 | 首期不自动跳下一首 |
| error | 不可恢复、鉴权失效或用户取消恢复 | 显示原因和明确的重试/重新登录入口 |

事件至少处理 `loadedmetadata`、`playing`、`pause`、`waiting`、`stalled`、`seeking`、`seeked`、`timeupdate`、`ended` 和 `error`。只有 `playing` 与进度前进等实际证据能够证明播放；`canplay` 不等于用户已允许输出。正常 `ended` 不触发恢复。

### W3.4 Range 定位与停止

`seekMode=byteRange` 时使用该输出实际 `seekable` 范围和 Server 的曲目范围检查目标，再交给媒体元素定位。浏览器负责具体 Range 请求，Web 不切片下载、不拼接音频字节。Server 输出资源固定版本，不能在同一 URL 下替换文件内容；浏览器发出或未发出某种 Range 模式须以网络记录为准。

停止操作递增代次、取消未完成控制请求、暂停音频、清空 `src` 并释放缓冲，然后关闭已知会话。暂停只暂停媒体，不等同于停止或销毁会话。页面关闭通知不可靠，不把清理正确性建立在 `unload` 必达上；Server 必须回收过期会话和处理进程。

### W3.5 故障与快速操作

每次逻辑操作带唯一标识。歌曲代次与定位意图代次分别维护：切歌/停止后废弃旧会话，旧响应和旧媒体事件不能影响新歌曲；同一会话内的 seek/recover 则共用 W4.6 的串行队列，在途响应即使已被新定位意图替代，也须确认服务端当前 attemptId，不能只丢弃响应后继续使用旧尝试。快速点击 A、B、C，最终只能播放 C；A/B 的请求取消、事件、`play()` 拒绝或迟到恢复结果不能改变 C。重复 error/stalled 合并为当前尝试的一次恢复意图，不并发派发恢复与定位；401、403、损坏媒体、网络中断分别保留可观察原因。

### W3.6 实际验收

- 从临时目录扫描出兼容音频，在真实浏览器点击播放，确认 `playing`、持续增长的 `currentTime`、真实媒体请求及 Server 的正确资产记录；手工完成一次听音确认。
- 暂停后时间停止，继续后前进，定位后从目标附近继续，停止后不再发声且会话释放；误差范围由样本编码与 Server 输出约定确定并记录。
- 连续快速切三首、在加载中停止、刷新文件列表、刷新页面、退出登录及播放中断网，状态和资源均正确收敛。
- 浏览器网络层验证流鉴权、Range/206/416 及固定表示的验证器；不能仅在 HTTP 单元测试中证明接口就声称浏览器定位已可用。
- 至少用一个真实浏览器完成自动化完整链路，并在项目目标 Windows 浏览器做手工听音；测试报告注明浏览器版本及未覆盖组合。

**P3 交付门槛：** 用户按 README 配置 Server、扫描目录、打开 Web，就能从真实列表选择兼容文件并播放。未达到这一结果不能把阶段标记完成。

## 8. P4：处理后输出、DSP 与曲目时间定位

1. **W4.1 协商处理输出：** 让 Server 针对实际能力返回 `deliveryMode=processed` 与确定的输出 profile。Web 显示简短“服务端处理中/服务端处理输出”状态；使用测试配置请求一个简单 DSP，不建立复杂效果编辑器。
2. **W4.2 保持新表示隔离：** 确认当前会话的新 `attemptId/representationId`，实际选用该输出时加载返回地址并清理旧缓冲；队列中仍有更新定位目标时，可跳过中间输出的播放。不能把原始音频 Range 偏移应用到转码输出。输入版本、处理配置或输出起点改变都走同一路径。
3. **W4.3 时间换算：** 第一轮只启用时间映射已验证的处理链；按契约将输出时间换成曲目位置，例如无变速且映射为平移时为 `positionOriginMs + currentTime * 1000`。不对变速/裁切链假定相同公式，未支持的时间映射必须由 Server 拒绝或声明不可定位。
4. **W4.4 timeRestart 操作：** 提供简单的“曲目位置（秒）”输入与跳转按钮，按 `seekableRange` 校验后将曲目毫秒位置交给串行队列。取得最终待播放目标的 Server 描述后，重新加载并依据用户原来是播放还是暂停恢复意图；不能再次把曲目绝对位置写入新片段的 `currentTime`。
5. **W4.5 原生控件边界：** 原生 audio 时间轴表示当前输出资源；处理输出可能只是从新起点生成的片段。页面单独显示整首曲目位置，并标明原生时间轴属于当前输出。原生滑动只按该片段实际可定位范围工作，不能宣称它能定位整首原曲；`seekMode=none` 时禁用应用的跳转入口。
6. **W4.6 串行控制队列：** 每个会话的 seek/recover 共用一个队列，最多一个在途请求；连续定位只合并保留最新待定位目标，歌曲代次与定位意图代次分开。只要仍属同一活动会话，在途成功响应即使已有更新目标，也先更新已确认的 `attemptId`，可以暂不播放中间输出；下一请求使用这个新尝试和独立 `Idempotency-Key`。同一操作的有界重试使用同一键，取消 fetch 不等于撤销服务端操作。结果不明时先用同键确认结果，仍不能确认则停止自动控制并提示显式重新播放，不能盲发基于旧 attempt 的新请求。切歌/停止废弃旧会话，旧响应只作清理，不能影响新歌曲；定位失败也不能继续显示成功的位置。
7. **W4.7 输出不支持：** 即使能力探测声称支持，真实解码失败也要报告本次输出 profile，交由 Server 在预算内选择其他兼容输出。Web 不自行遍历所有格式或无限创建转码任务。
8. **W4.8 实际验收：** 选择目标浏览器不能原生播放的输入，经真实 Server 音频插件解码、简单 DSP、编码/封装后播放；验证首音、持续进度、处理中取消、插件失败和跳至已知音频标记位置。覆盖连续定位、定位与恢复竞争、响应丢失后同键重试、结果仍不明以及在途控制期间切歌，确认队列最多一个在途且不会反复使用旧尝试。对正确生成的输出做浏览器播放验收，不能仅证明 FFmpeg 命令返回 0。

**P4 交付门槛：** 在兼容性记录中至少有一组实际失败的原始输入与成功的处理后输出对照；真实浏览器必须在整段输出尚未生成完时已有声音，并保留首音与处理完成的时序证据。同时记录 timeRestart 的新尝试、新地址、目标曲目时间和实际结果。预先完整生成后播放只允许作为阶段内过渡，须明确首播等待，不能通过 P4 完整验收。

## 9. P5：资产版本与匹配能力接入

1. **W5.1 显示增量信息：** 列表仅按需显示 Server 提供的格式、码率和可用性；摘要/指纹是后端匹配材料，不要求 Web 下载音频计算。缺少摘要不影响已有播放链路。
2. **W5.2 处理版本变化：** 列表刷新发现条目变化时不改活动会话；Server 宣告活动资产失效后，通过恢复接口获取新描述。刷新后的时长或名称不能使旧流自动成为“新资产”。
3. **W5.3 消费恢复决定：** 同源同资产的输出重建，只要输入/输出时间映射已验证且目标可定位，不要求曲目已关联 Recording。跨源续播则须确认同一 Recording、具有绑定两端资产版本的独立时间轴兼容证据且目标支持所需定位，再接受 Server 指定的新尝试；P5 先实现该消费契约与状态处理，实际跨源联调在 P7 完成。`resumeDecision` 要求从头开始时只显示“从头播放/取消”两个动作，保留用户决定。
4. **W5.4 禁止浏览器猜测：** 不依据相同标题、相近时长、相同摘要字段或指纹相似在 Web 侧判定可续播；不在新旧输出间拼接字节或沿用未验证的位置。
5. **W5.5 验证：** 用真实可重复样本覆盖已支持的同源 URL 失效、资产版本改变和同资产输出重建；对未来跨源的映射成功、时间证据缺失、目标无法定位、连续失败达到预算及恢复期间切歌，先做明确标为 Mock 的契约/状态测试，不声称跨源已经可用。Server 预算耗尽后页面应停下来提供操作入口；真实跨源续播与声音位置在 P7 验收。

本阶段不增加合并/拆分 Recording 的管理 UI；需要人工修正时使用 Server 提供的管理接口或工具，Web 只保持来源身份和状态正确。

## 10. P6：独立 Scraper 的最小衔接

1. **W6.1 约定刷新影响：** 后端选用歌词/封面或更新文本元信息后，列表下一次刷新可显示新的名称等必要字段；媒体对象缺失、刮削排队或失败不阻塞播放按钮。
2. **W6.2 保持首期页面：** 自动/手动刮削、候选预览、逐字段选用与写回先通过 Server API/管理工具验收；Web 不因该阶段追加复杂候选比较器、歌词编辑器或封面管理页。
3. **W6.3 如增加简单封面：** 只读取鉴权后的 MediaObject 引用，失败使用文字占位；不接受原始磁盘路径，不自动显示未经处理的 HTML/SVG 等活动内容。此项可选，不能成为 P3/P4 的回归障碍。
4. **W6.4 写回回归：** 默认不写音频；管理员显式启用写回并成功产生新资产版本后，按 P5 行为验证旧会话和列表，不因封面变化擅自清空歌曲身份或播放记录。

**P6 Web 验收：** 无刮削插件、刮削失败、人工选用元信息以及授权写回四种情况下，简单列表和播放保持可用；高级元数据交互留给后续范围。

## 11. P7：在线平台 Provider 的最小衔接

1. **W7.1 能力驱动：** 只显示 Server 向当前用户暴露的已配置 Provider 和已纳入库的曲目；平台登录、目录导入和推荐导入先由插件管理工具/API 完成，不将每个平台登录流程直接写死进文件列表。
2. **W7.2 沿用统一播放入口：** Web 按 `sourceTrackId` 创建会话，由 Server 处理平台凭据、短期 URL 和播放权限；不能把平台账号 cookie 或密钥下发到普通页面。
3. **W7.3 呈现部分失败：** 平台暂不可用、需登录、无播放权限、试听和地区/订阅限制用明确状态呈现。一个来源失败不隐藏其余本地或在线曲目，不把可搜索/可推荐等同于可播放。
4. **W7.4 尊重平台交付方式：** 网易云、QQ 音乐、Apple Music 等逐个平台验证；若 Apple Music 的受保护内容需要官方 MusicKit 播放路径，先作为独立适配提案验证，不能假定普通 `<audio src>` 或 Server 转码能够交付。相关平台和开源参考由 [Server README](../../server/README.md) 登记。
5. **W7.5 推荐范围：** Provider 可提供推荐能力，但本期不新增推荐首页。由后端导入/绑定后，能够播放的来源曲目可通过既有列表验收；未来推荐 UI 再按实例、账号和部分成功状态扩展。
6. **W7.6 验证：** 离线测试使用脱敏的固定 Provider 响应覆盖过期、限流、授权失败和部分成功；真实平台冒烟测试单独记录账号前提、时间和结果，不能放入不稳定的默认 CI，也不能用 Mock 结果宣称平台可用。
7. **W7.7 跨源恢复联调：** 以实际音频及真实 Provider/Server/浏览器链路验证符合条件的跨源续播：确认同一 Recording、绑定输入/目标资产版本且覆盖位置的独立时间映射、目标可定位，然后故意使当前来源失败，确认新尝试从正确声音位置继续。另测只有指纹相似或缺时间证据、目标无法定位、映射失败等情况，页面必须要求“从头播放/取消”，不能静默猜测位置；还需覆盖恢复与定位共用队列、快速切歌和预算耗尽。此项可用获授权的本地测试来源建立可重复链路，真实平台能力另按 W7.6 核验。

**P7 Web 验收：** 至少对一个实际可合法播放的在线来源完成统一入口播放与过期恢复测试，并完成真实跨源符合条件续播及无证据时从头确认的验证。其他来源按已验证能力明确标记；某个平台尚不可播放不影响本地播放交付。

## 12. P8：交付、兼容性与最终验收

1. **W8.1 静态制品：** 生成独立 `dist/`，记录 Web 版本、兼容协议范围与构建信息。运行时 API 使用同源相对路径，避免将个人 Server 地址、token 或平台账号写进 JavaScript 包。
2. **W8.2 部署联调：** 分别验证开发代理，以及生产静态站点 + 同源 API/音频反代。选择 Server `--web-root` 本地方案时只复制 Web 制品；确认静态路由不会吞掉 `/api` 错误，反代不会破坏 Range、cookie、流式响应或取消。
3. **W8.3 兼容性记录：** 建立 `docs/compatibility.md`，记录操作系统、浏览器与版本、输入/输出格式、MIME、交付模式、seek 模式、通过/失败/未测和复现步骤。优先验证用户目标 Windows 浏览器；扩大到 Firefox、Safari 等前先取得对应实测条件，未测不记为支持。
4. **W8.4 文档：** README 写明前提、固定依赖版本、实际可执行命令、Server 配置入口、最短播放步骤、样本来源、鉴权和已知限制。现有 [Web 设计](design.md) 保留长期职责，明确哪些仍在计划中。
5. **W8.5 测试分层：** 单元测试证明状态和时间换算；契约测试证明 DTO/错误兼容；真实 E2E 证明浏览器与 Server 协作；手工听音证明至少一条实际可听链路。各层记录其证明范围，模拟 `playing` 事件不能证明解码成功。
6. **W8.6 清理与回归：** 停止、退出、关闭页、网络失败和 Server 重启后，不遗留长期无主转码任务或重复音频。自动化检查键盘顺序、按钮名称和关键状态可达，手动验证原生媒体控件及中文文件名。

### 12.1 必须通过的最终场景

| 场景 | 可观察结果 |
| --- | --- |
| 干净启动、扫描并打开 Web | 登录后显示实际文件，空库和未完成扫描可区分 |
| 原生兼容文件 | 实际播放、暂停、继续、定位、停止成功 |
| 目标浏览器不兼容文件 | Server 处理为已验证输出后实际播放成功 |
| 处理后定位 | 新尝试/新输出按正确曲目时间继续，原生片段时间不冒充总时间 |
| 快速切歌和加载时停止 | 仅最后有效操作生效，没有旧曲目重新发声 |
| 库刷新、NAS 离线 | 不拼接不同修订，不清空最后有效内容，不擅自改活动资产 |
| token/cookie/CSRF | token 不持久化，合法会话可播放，越权/跨站控制请求被拒绝 |
| 来源失效与跨源恢复 | 按 Server 决策有限恢复，证据不足时要求从头或取消 |
| 退出登录、页关闭、Server 重启 | 页面状态可恢复，后台会话和处理进程最终释放 |
| 无封面、无歌词、插件失败 | 列表和可用来源播放不依赖装饰性信息 |

每项完成后记录对应实现提交、测试命令、运行环境和残留限制，再将阶段状态从“计划”改为“通过”。当前文档只列任务与标准，所有阶段均尚待实施。
