# 控制通道与能力变更订阅

登录成功或恢复会话后，Web 通过同源 Cookie 建立 `GET /api/v1/control` WebSocket，子协议为 `musicfs.control.v1`，首帧提交 `{ type: "auth", csrfToken }`。令牌不放在 URL。连接由应用服务持有，页面切换和 React StrictMode 不会重复建立；退出登录、会话失效和开发热更新清理时关闭连接并取消待处理请求。

收到 `ready` 后按服务端下发的间隔发送应用层 `ping`，并以 `pong` 检测响应超时。默认间隔为 10 秒、超时为 30 秒；建立连接的等待上限为 10 秒。断开连接后使用 500 毫秒到 30 秒的有界指数退避重新连接，同时通过 HTTP 检查当前登录会话。401 清理登录状态；临时网络故障保留重连能力。

播放会话创建、定位、恢复和释放通过同一通道的 `request`/`response` 帧传输，使用独立请求 ID 关联响应。等待连接就绪的请求受超时和取消约束，最多保留 128 个待处理请求。已经发送的写请求在断线或超时后报告结果未知，不自动重放。响应错误沿用 API 错误结构。登录、普通资源查询和音频流仍使用 HTTP；浏览器播放器继续直接读取返回的流地址，保留 Range 与时间重启定位。

收到 `ready` 或 `capabilities.changed` 的 `{ revision, sequence }` 后，重新请求当前页面使用的授权来源列表，包括曲目来源、设置页来源、在线搜索来源和导入歌单来源。能力以 `/provider-instances`、`/online-instances` 的实际响应为准，不使用事件推断权限或插件状态。首次能力事件也会刷新，以覆盖连接就绪与订阅建立之间的变化。同次连接内的重复版本通知合并；无效通知忽略；重连始终重新读取授权列表。

自动验证：`npm test` 覆盖鉴权、请求关联、去重、重连、心跳超时、取消、结果未知及会话隔离；`npm run test:e2e -- tests/e2e/capability-events.spec.ts` 使用真实 Server 与开发代理验证插件停启后的刷新、WebSocket 中断重连和注销。播放界面夹具通过真实 WebSocket 帧应答控制请求，音频夹具保留 HTTP。

## 任务与扫描进度

首次打开时通过 HTTP 读取当前快照。在控制通道收到 `activity.changed` 后，按 `data.resources` 指定的范围重新读取。每次连接就绪也会刷新正在关注的资源，补齐断线期间的变化。空闲页面仅维持连接心跳。

| 资源 | 网页端刷新范围 |
| --- | --- |
| `tasks` | 全局任务角标和选定范围内的任务页 |
| `scans` | 当前跟踪的来源扫描、元数据进度与结果 |
| `pluginJobs` | 已打开插件设置中的任务状态，保留正在编辑的字段 |
| `playlistSync` | 正在跟踪的远程歌单同步任务，成功后更新歌单列表 |

尚在应用或等待排空的目录配置通过 `capabilities.changed` 确认操作结果。平台账号授权仍按来源返回的间隔提交授权确认请求。

`tests/e2e/task-queue-real.spec.ts` 在独立 Server 上通过另一个请求提交刷新，验证已打开的任务面板会收到 WebSocket 通知并显示终态。`tests/e2e/playlist-sync-events.spec.ts` 通过控制通道夹具检查同步任务在断线期间完成时的恢复行为。

服务状态角标直接订阅连接、心跳和本地生命周期状态。没有生命周期事件的远端连接只显示在线，手动健康检查继续使用 HTTP。服务实例变化会停止旧播放、取消旧命令并重新读取就绪信息及登录会话。已发送的播放创建在取消或超时后保留最多 30 秒的同连接清理记录，迟到的成功会话立即释放。清理记录与待处理请求总数限制为 128。
