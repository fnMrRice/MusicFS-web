# 一键合并重复音乐

曲库工具栏提供“一键合并重复音乐”，无需逐首勾选。服务端通过 `GET /matching/revision` 返回 `bulkMergeAvailable: true` 时展示入口；旧服务端继续使用已有逐首合并和重复识别功能。

- **按分数合并**：默认最低分数为 80，可输入 0—100 的整数；提交满足最低分数的待确认候选。分数代表核对优先级，不是相同概率，使用前应完成重复识别。
- **合并重名重作者**：按规范化后的完整曲名和作者集合相等合并，不需要先运行候选识别；曲名或作者为空的曲目不参与。

两种方式都处理当前用户在全部来源中可见的当前可用且资产有效的曲目，不受当前来源筛选、分页或选中项影响；缺失或不可用曲目不参与新匹配，但已经关联的旧组仍整体保留。服务端保留来源版本和原始文件。已排除、录音冲突和每组超过 256 个来源版本的分组会跳过；手动解除关联的曲目不会被再次自动合并。相同曲名和作者也可能对应不同录音，用户应根据曲库情况选择规则。

界面通过 `POST /matching/bulk-merge` 提交修订号、模式及分数阈值，展示合并组数、涉及的来源版本数、跳过组数及无匹配结果。提交由登录会话持有，可关闭弹窗或切换页面；成功会刷新全部已缓存曲库，并在返回曲库时展示结果。

网络中断或响应无法确认时，请求及幂等键保存在当前用户和服务端隔离的会话存储中；参数和其他关联操作锁定，刷新页面后可用“继续确认关联结果”重试原请求。修订冲突不会自动改写请求重试，需要刷新后重新确认。退出登录清除内存结果，防止跨用户显示。

自动验证包括阈值边界、模式参数、旧端兼容、返回统计验证、网络恢复时请求与幂等键不变、全局互斥、冲突后显式确认、跨页面完成和全部已缓存来源刷新；浏览器模拟测试还覆盖移动端结果布局。真实服务端验证由 `tests/e2e/bulk-merge-real.spec.ts` 单独覆盖。

真实服务测试默认编译相邻的 `server/`，使用临时曲库验证空标签不合并、评分合并、原键重放、重启持久化及原文件字节不变。需要验证独立服务端检出时，可通过 `MUSICFS_E2E_SERVER_SOURCE` 指定源码目录。并行开发的无关修改暂时不能编译时，`server/scripts/prepare-bulk-merge-test.ps1` 可导出已提交基线并叠加本功能文件用于隔离排查；最终集成验证仍应使用当前工作区。
