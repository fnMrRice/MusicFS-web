# Web 界面开发方案：TypeScript + React

状态：实施依据 v0.1，2026-10-10。React 界面已按本方案落地，实际交付及未完成项见 [React 交付记录](react-validation.md)。下文保留规划时基线，不作为当前功能完成声明。

## 1. 目标、依据与端差异

本轮先完成 Web。桌面 Client 在 Web 完成后另行设计与实施，可以增加桌面能力；本轮不建设桌面宿主、窗口适配或跨端组件发布体系。

设计依据按以下顺序使用：本文件的 Web 差异与用户最新约定、[共享布局](../../docs/ui-design.md)、[曲目列表](../../docs/ui-tracks.md)、[搜索页](../../docs/ui-search.md)。协议和身份语义以[跨端架构](../../docs/architecture.md)及 [Server 契约](../../server/docs/contracts/README.md)为准。

## 3. 技术方案与工程组织

确定采用 TypeScript 严格模式、React、现有 Vite 和 npm 锁文件，继续交付静态 `dist/`。无需引入 SSR 或新的业务服务端。其他库选择属于实施方案，版本兼容性在 R0 验证，不能把文档选择当作已通过构建。

| 层次 | 方案 |
| --- | --- |
| React 工程 | 增加匹配版本的 `react`、`react-dom`、类型包和 `@vitejs/plugin-react`；启用 `jsx: react-jsx`；入口迁移为 `src/app/main.tsx` |
| 路由 | 采用 React Router 的 hash 路由方案，保留当前静态托管方式，避免要求 Server 为每个前端路径增加回退；在 R0 锁定兼容版本并验证刷新与前进后退 |
| 样式 | CSS Modules + CSS 变量；优先复用小型语义化组件，不以大型组件库默认皮肤代替已确认界面 |
| 数据 | 复用现有请求层；以受控查询状态管理游标与取消，不同时引入另一套未经必要性验证的数据缓存体系 |
| 全局状态 | React Context 注入服务；外部播放器／鉴权／查询 store 提供订阅，组件用 `useSyncExternalStore` 接入；局部菜单与输入使用组件状态 |
| 图标 | 统一 SVG 图标资源、尺寸和线宽；图标按钮必须有名称与可见焦点，不用字符表情代替产品图标 |
| 测试 | 沿用 Vitest / Playwright；需要组件交互测试时在 R0 增加 React Testing Library 与适配环境，版本锁定后记录 |

建议目录按职责逐步建立，不一次性生成空模块；源文件尽量不超过 400 行。

```text
src/
  app/                 # main.tsx、路由、服务组合、应用级错误边界
  api/                 # 现有同源客户端及按领域划分的适配器
  auth/                # 脱离 DOM 的会话 store、登录命令
  layout/              # AppShell、Sidebar、Header、AccountMenu
  components/          # IconButton、Tooltip、Menu、Checkbox、状态视图
  features/
    library/           # 曲目页、分类、筛选、排序与查询状态
    search/            # 搜索框、四类结果、来源分区与查询状态
    recommendations/   # 推荐来源分区和歌单卡片
    playlists/         # 歌单详情与管理
    collection/        # 我的收藏、最近播放
    settings/          # Web 设置页与主题入口
  library/             # 当前游标状态迁移期间保留，不复制两份规则
  player/              # 现有核心、audio 适配、store、PlayerBar、QueuePanel
  styles/              # 主题变量、全局基础样式
tests/
  unit/                # 状态、命令、组件交互与协议边界
  e2e/                 # 真实 Server、媒体及整页行为
  fixtures/            # 明确标记的测试数据，不能回退为生产假数据
```

路由内部地址建议如下；它们是前端路由，不能据此推导服务端端点。

| 路由 | 内容 |
| --- | --- |
| `#/library` | 曲目列表；首轮默认落地页，可先使用当前真实来源 |
| `#/search` | 独立搜索；`q`、来源、结果类型写入路由查询状态，草稿输入不立即发请求 |
| `#/recommendations` | 推荐页，无可用来源时显示说明和进入音乐库的入口 |
| `#/playlists`、`#/playlists/:id` | 歌单管理、详情 |
| `#/favorites`、`#/recent` | 我的收藏、最近播放 |
| `#/albums/:id`、`#/artists/:id` | 专辑、歌手详情；参数同时保留来源身份，禁止按同名合并 |
| `#/settings` | 当前身份、连接状态、播放偏好等 Web 可用设置 |

AppShell 与播放器位于路由内容出口之外；路由切换不重新创建播放服务。直接访问受保护路由先恢复会话，401 进入登录；浏览器前进后退恢复已提交查询和内容位置。URL 中不得出现令牌、媒体授权地址或 Server 文件路径。

## 4. 页面结构与交互实现

### 4.1 共享外壳

应用根使用两列两行布局：侧栏与主内容在上，全宽 PlayerBar 在下；高度跟随可用视口。侧栏内部为 Banner 和 `minmax(0, 1fr)` 滚动区。主内容为固定 Header 与可滚动页面区域，账号头像位于 Header 最右侧；关键 flex/grid 子元素设置 `min-height: 0`，避免整页滚动带走账号或播放栏。

宽屏起始值：侧栏约 240 px、播放栏约 96 px、页内边距 24 px；颜色用命名 CSS 变量统一，逐页对照效果图调整。在 1280×800 和 1440×900 验收主要布局；窄视口允许收窄导航和表格横向滚动，保持账号、播放控制和键盘焦点可达，不在本轮另立移动端产品设计。

两个侧栏分组分别保存展开状态；新建歌单按钮不触发折叠。主题、音量与分组状态可保存在本机非敏感偏好中，按实例和用户隔离；退出后不让下一账号看到上一账号的搜索记录或数据缓存。

设置、换肤纯图标显示 tooltip，约 400 ms 悬停或键盘聚焦触发；Escape 关闭。用户三点或用户区右键打开菜单，菜单使用浮层避免滚动裁切，关闭后焦点回到触发按钮。Web 不注册迷你模式或窗口控制快捷键，不调用 `window.close()` 模拟桌面退出。

### 4.2 曲目列表

分类页签、来源与格式筛选、仅收藏／仅可播放、更多筛选、列表内查找、排序按共享设计排列。表头吸顶，曲名列含封面和版本信息；未知元信息用占位，不把格式等同音质。当前 Web DTO 没有专辑／封面等完整字段，接入前按[接口依赖](react-api-readiness.md)处理。

排序与过滤必须覆盖完整查询，不能只对已返回部分排序后冒充全库结果。当前仅有来源过滤时先支持该真实能力，其余入口按依赖矩阵显示未支持说明，不在生产中用截图数字或静态歌曲补齐。

checkbox 常驻，勾选不触发播放；表头全选保存当前列表的全选状态，包括尚未加载的条目，追加项自动选中。单独取消时记录稳定来源曲目 ID 并显示部分选中状态，重新全选清除排除项。普通选择保存选中 ID，不用行号或数组索引。选中后操作栏替换为选择范围、加入队列、添加到歌单、收藏、清空选择，未选中不显示“批量选择”按钮。曲目列表的全选操作通过 `batch/exclude` 和当前来源、修订提交；收藏、歌单、合并在服务端处理，队列只读取紧凑引用，不为操作加载全部曲库页。刷新、来源及查询范围变化清除选择；清空选择不撤销已经提交的服务端写入。其他分页表格的选择解析范围见[分页说明](pagination.md)。

### 4.3 独立搜索

搜索框在页面内，Enter／搜索按钮提交，中文输入法组合输入期间不提交；清空回到搜索前状态。最近搜索只按当前用户在本机保存，并可删除；不伪造热搜。

结果有曲目、专辑、歌手、歌单四类：曲目使用共用表格与 checkbox；专辑用方形封面卡片；歌手用圆形头像卡片；歌单显示封面、创建者与来源。专辑、歌手有独立结果和详情，不从已返回的曲目页临时去重生成“完整结果”。查询计数未知时省略数字。

单一来源按其排序与游标加载；“全部来源”按来源分区保留各自排序、失败和结束状态，不比较不同来源的相关性分数。每个分区使用同一页面滚动区中的末尾哨兵与自己的游标，不建立多个滚动框。切换类别或来源保留关键词，重置对应请求代次、选择与列表位置。

曲目工具栏使用“播放结果”“加入队列”；需要处理整个结果集时必须有完整结果队列能力，不能偷偷只播放已返回的几条。点击歌单只打开详情，明确导入／绑定后才进入用户歌单库。

### 4.4 推荐、歌单与设置

推荐按来源展示卡片，分别显示过期、无权限和部分失败，未接入推荐时保留真实的不可用说明。歌单详情复用曲目表格；管理页提供新建、导入／绑定、重命名、同步状态与聚合规则入口，服务端未支持的操作不可伪造成功。

我的收藏、最近播放依赖明确持久化方案与接口，不能把登录账号的个人数据默认共享给其他用户。Web 个人信息卡通过 `/me/profile` 读取及修改本人昵称，未填写时显示服务端用户标识；昵称只是展示资料，不作为账号身份。头像沿用默认图形，不硬编码效果图账号。资料接口失败时保留真实用户标识，编辑弹窗显示错误并允许重试，不把未保存输入当作已保存昵称。

设置首轮包含当前实例／连接状态、主题偏好、播放偏好和退出登录；主题通过换肤按钮也可进入。只暴露实际协商可用的播放选项；目录、插件、平台凭据管理需单独验权和设计，不把 Server 文件路径或密钥放进浏览器。

## 5. 查询状态与动态加载

查询键包含实例、用户、页面领域、来源、已提交关键词、结果类型、分类、筛选和排序；不包含当前播放器位置。每个查询维护不可变结果快照、修订、下一游标、请求代次、首批／追加状态、错误与结束标记。

1. 初次请求不带游标；切换查询参数时取消旧请求并增加代次。响应必须同时匹配查询键与代次才能发布。
2. 使用结果滚动容器作为 `IntersectionObserver` 的 root；接近末尾时自动追加，一次只允许一个追加请求。同一游标不得重复成功消费，不从行数计算游标。
3. 追加使用返回的 `nextCursor` 与原查询参数；固定修订不符时不拼接。列表修订失效提示刷新，以新首批替换旧数据；不将上一代选中行应用于新版列表。
4. 初次加载显示骨架；追加时末尾显示“正在加载…”，不占固定页脚。失败保留列表与位置，显示重试入口并暂停自动重试；用户重试仍用失败的游标。
5. `nextCursor` 为空才表示结束；成功空批但游标前进时允许有界继续，连续无新增数据或游标不前进时停止并显示可重试异常，防止哨兵触发死循环。
6. 自动追加保留选中项与滚动位置；更改查询或刷新新修订时清空选择并说明。没有分页器、已加载计数或加载更多按钮。
7. 测量长列表后再引入虚拟化；不能因虚拟节点卸载丢失选择或键盘焦点。测试至少包含 1,000 条数据和触底重复触发，不以 DOM 中只剩可见行推断选中范围。

当前 `LibraryState` 已有单在途、去重和代次控制，但 `CURSOR_EXPIRED` 会自动重取首批；迁移需改为上述可解释刷新状态，沿用其协议保护并更新竞态测试。内部仍是游标分页，界面呈现为连续滚动。

## 6. 播放核心与 React 的连接

当前 `PlayerController.state` 存在原地修改，且只有单个 `onChange` 回调；不能直接把它当作多个 React 组件的 store。增加适配层或修改其通知接口：事件发布时生成新的不可变快照，无变化时返回缓存的同一快照；`subscribe` 返回取消订阅函数，多个订阅互不覆盖。列表状态同样使用稳定快照。[React 外部 store 约定](https://react.dev/reference/react/useSyncExternalStore)

服务由应用生命周期持有，React 组件只订阅和发送明确用户命令。禁止在 render 或仅因路由挂载的 Effect 中创建播放会话；开发模式保留 StrictMode，订阅／观察器清理应可重入，不能导致双重媒体、双重会话或退出操作。[React StrictMode](https://react.dev/reference/react/StrictMode)

| 控件 | 开发要求 |
| --- | --- |
| 播放／暂停 | 当前控制器尚无直接公开的暂停／恢复命令；增加命令与快照字段，处理 `play()` 拒绝，以媒体事件确认状态 |
| 音量／静音 | 扩充 `AudioPort` 和观察事件，保存用户偏好；每次替换媒体元素重新应用，不在两端额外重复 DSP |
| 进度 | 使用曲目毫秒映射；`none` 禁用拖动；`byteRange` 校验协商范围和实际 seekable；`timeRestart` 继续走串行控制队列 |
| 上一首／下一首／模式 | 新增 Web 内存队列控制层，条目固定来源身份；队列不依附当前 DOM 或当前路由，不默认宣称跨设备同步 |
| 故障 | 保留恢复预算、同键重试、旧 attempt 忽略；无法证明续播时让用户选择从头播放，不能猜进度 |
| 歌词／封面 | 走受鉴权内容引用；无数据用占位；接口未完成时说明状态，不从私人目录或第三方网址偷偷补齐 |
| 退出／401 | 停止播放器、释放会话、取消请求并清空用户数据；关闭页面仍依赖 Server 的会话超时兜底 |

最多一个活动 `HTMLAudioElement`，按既有会话／表示替换，不要求同一个 DOM 元素永久存活。React 不改写适配器拥有的媒体节点；原生控件从主界面移除前，必须先通过自定义控件的原流、处理输出和 NCM 回归。音频事件驱动局部播放器更新，不让每次进度变化重新渲染整个曲目表。

## 7. API、错误与安全

详见[接口现状与待补能力](react-api-readiness.md)。现有 `/source-tracks` 没有文档化的关键词、完整排序、专辑或歌手过滤参数；不得因为设计里有下拉就向接口发送自创字段。新增接口、字段、Schema 和事件由 Server 仓库负责，双方确定版本后 Web 才接入。

复用同源 cookie 与 CSRF：登录凭据不进 URL、日志、持久存储或构建环境，退出也执行鉴权约束。React 文本默认按文本渲染，不用 `dangerouslySetInnerHTML` 高亮搜索关键词；服务端错误展示中文可操作信息，程序日志使用英文且脱敏。

未支持、正在加载、真实空结果、权限不足、来源离线和请求失败分别建模。可用性不等于已证明可解码；多来源部分失败不抹掉其他来源结果。每个页面有错误边界，但错误边界不能代替异步请求错误处理。

## 8. 验证与验收清单

现有单元和 E2E 命令继续使用；只在实施后记录新的通过结果。文档编写不构成 React 构建或浏览器验收。

| 层次 | 必须证明的行为 |
| --- | --- |
| 工程 | `npm ci`、`npm run typecheck`、`npm test`、`npm run build`；无原生 DOM 与 React 双入口 |
| 外壳 | 账号／Banner／播放器固定；两组独立折叠；设置在换肤左侧；无桌面窗口按钮、残留分隔线或快捷键 |
| checkbox | 勾选不播放，全选包含未加载项，追加项自动选中，单项排除和部分选中状态正确，批量操作不遗漏分页，查询变化清空选择并取消待执行动作 |
| 动态加载 | 重复触底单请求，乱序忽略，游标失效不混修订，错误可重试，无下一游标即停止，无页码与加载数量 |
| 搜索 | 中文输入法、四类结果、未知计数、来源能力不足、部分失败、取消旧查询、返回恢复位置 |
| 播放 | 切页连续播放，快速切歌／连续定位、自动播放被拒、恢复与暂停意图、音量及队列；原流／处理／NCM 沿用真实媒体证据要求 |
| 鉴权 | 刷新恢复、401 清理、退出、CSRF 拒绝、用户切换后无旧数据泄漏 |
| 视觉与可访问性 | 两个宽屏视口、缩放／窄视口、中文长标题、无封面、键盘焦点、tooltip、菜单、复选框与进度条标签；减少动画偏好可生效 |

关键状态与交互写针对性测试，不写只证明某个 JSX 存在的测试。端到端优先按 role、label 和可见名称定位；Mock 只验证界面，实际 Server 和音频测试才可证明播放。浏览器兼容性按实际结果记录，不沿用旧版本的通过结论覆盖 React 新界面。

## 9. 实施顺序与完成门槛

| 阶段 | 主要工作 | 完成门槛 |
| --- | --- | --- |
| R0 基线与契约 | 保存当前测试基线；确定新增依赖版本；核对待补 API 与各端范围 | 依赖兼容清单、真实接口矩阵；当前代码与计划明确区分 |
| R1 React 接管 | 入口、路由、服务注入、脱离 DOM 的鉴权与播放器订阅 | 登录恢复和已有真实播放通过；StrictMode 下无重复副作用 |
| R2 外壳与列表 | 固定布局、图标、主题、折叠分组、曲目表、checkbox、动态加载 | 当前真实来源可用，竞态与键盘检查通过；未支持条件诚实显示 |
| R3 自定义播放器 | 播放暂停、音量、曲目进度、队列及错误操作 | 原流、timeRestart、NCM 真实回归；切页不停止播放 |
| R4 搜索与分类 | 协议就绪后接四类搜索、来源状态、卡片详情及全库过滤排序 | 真实结果可遍历；失败／结束正确；不可仅凭 Mock 宣称完成 |
| R5 内容与个人区 | 推荐、歌单管理与详情、收藏／历史、必要设置 | 对应接口和权限验收通过，导入／绑定显式，数据不跨用户混用 |
| R6 交付 | 全量回归、视觉核对、同源部署、运行与进度文档更新 | 干净环境构建与真实浏览器通过；残留能力逐项列明，再评估 Client |

R1—R3 可复用当前接口先交付新的 Web 基础体验；R4—R5 的后端依赖未满足时，基础体验可验收但完整 UI 功能不能标记完成。每阶段保留可回溯的小提交，不与 Client 工作混合；不在本方案中替 Server 排定未获确认的实现工期。

迁移完成前保留可回退的 Git 基线，避免长期保留两套运行时界面；回退通过恢复已验证提交完成，不让生产页面同时启动两套播放器。构建产物、凭据和测试运行目录不提交，新增截图按所在仓库 Git LFS 规则管理。
