# 固定修订分页

首次请求不带 cursor；后续只使用上次响应的 opaque cursor。每个列表代次固定 libraryRevision；修订不同的页面不可拼接。

刷新和切换来源递增列表代次并中止旧请求。迟到响应必须核对代次；刷新期间保留最后一次成功的数据，失败时提示可能过期。来源按独立缓存显示，离开页面取消在途请求；退出清空所有缓存。普通刷新不改变播放器或活动资产。

同一来源按 sourceTrackId 去重，自动追加只能有一个在途。游标失效保留旧列表并提示显式刷新，不能重用失效游标或混入新修订。游标不前进、重复消费或连续三次无新增结果时停止自动追加，显示错误与重试入口。

W0.3 完成：状态/取消规则核对；竞态测试在 W2.6 实现。

## React 界面迁移

React 页面已使用上述连续滚动规则，没有分页器、已加载计数或加载更多按钮。单项勾选保存稳定来源曲目 ID；表头全选保存当前查询的全选状态和单独取消的 ID，尚未加载的曲目也属于选择范围，追加时自动选中。尚未读完时显示“已选择全部曲目”及排除数量，完成后显示实际选中数量。清空、刷新、来源或曲库修订变化清除选择。

曲目列表的全选操作发送 `batch: true`、`exclude`、来源过滤、录音分组方式及两种修订。收藏、歌单和合并由服务端在事务内解析选择并执行，Web 不逐页读取全部曲目。收藏结果仅回传所选 ID，立即更新内存标记，下次打开收藏页面才刷新完整内容；歌单结果仅含 ID、修订和数量。浏览器播放队列需要完整顺序，单次请求紧凑曲目引用与展示信息，不返回全部版本或资产证据，不追加到曲库表格；队列引用仍随曲目数量增长。修订冲突要求刷新重新选择，合并继续遵守 256 个来源版本上限。分类、歌单等其他分页表格暂沿现有查询解析选择，不传普通曲库范围冒充其作用域。

1,000 条 Mock 曲目测试验证全选状态、失败重试和追加行为；批量接口测试验证不为操作追加曲库分页，不代表真实超大库性能基准。
